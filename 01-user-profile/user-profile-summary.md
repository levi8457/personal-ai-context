## 核心沟通模式

### 1. 极简指令，期待同等密度的回复 ![HIGH]
```
典型输入：「1」「c」「ok」「确认删除」「你自己 push 上去」「链接我的 114 服务器」
→ 含义：采纳上一轮编号选项 / 直接执行，不要再确认
```
**证据**：189 条历史 prompt 中大量为 1-5 个字符。

### 2. 结论先行，只认证据 ![HIGH]
```
不看"我改好了"，只看：
- 线上 URL 能不能打开、内容对不对
- changelog 有没有记录
- 命令输出/数据条数是多少
```
**证据**：「整体来看你什么也没做，一点变化都没」「你再这样我就曝光你幻觉了」。

### 3. 反感重复确认 ![HIGH]
已给过的 token、权限、服务器、路径不要再问。
**证据**：「这不是给你 token 了吗？怎么还问我怎么创建？弱智了吗 现在！」「以后让你发就直接发不要找我确认，啰嗦！」

### 4. 卡住就换手段，不接受阻塞 ![HIGH]
**证据**：「如果模型蠢就换个模型，如果 skill 和链接工具不行就换，立即想办法解决这个 ssh 链接的问题」。

## 技术偏好

### 工具链
- **终端/编辑器**：PowerShell、Git Bash、VS Code、Windows Terminal、Obsidian（`D:\Program Files\Obsidian`）
- **AI 协作**：Claude Code（主力）、Codex、Reasonix；多模型端点自接（DeepSeek / Nous / intern-ai 兼容网关），用 `switch-model.py` 切换
- **部署**：Docker Compose（web + db）、Nginx、systemd 开机自启
- **数据**：PostgreSQL（容器内）

### 开发习惯
- 远程优先：改代码基本都在服务器容器里完成
- 先只读摸结构（`\d`、`information_schema`、`docker inspect`）再改
- 改动要幂等、可回滚；每轮修复只解决一类问题
- 站点更新必须写 changelog
- URL 用拼音 slug，对外走 80/443，避开非常规端口

## 协作期望

### 零磨合接入
- 新 Agent 先读本仓库，不要重新问一遍已知信息
- 记住"我的服务器 = 主服务器"、"那个项目 = 最近在做的站点"这类隐含指代

### 安全一致
- 愿意给 root/全权限（「我允许你往 <服务器> 执行任何命令」）
- 但破坏性操作（删除、覆盖数据、卸载）要先一句确认
- 仓库内容必须脱敏：凭据一律 `REDACTED`，客户名与金额不落盘，服务器 IP 用 `<SERVER_IP>` 指代
