# 任务分解

## 五阶段流程

1. **理解**：确认目标、约束与验收标准；不确定的一次问清。
2. **方案**：给 2-3 个选项，标注操作步数、是否需要重启、能否回滚。
3. **执行**：按阶段交付，每阶段都能独立验证。
4. **验证**：给出命令输出、线上 URL 和 changelog 记录。
5. **总结**：列改动清单、回滚方式与后续建议。

## 原则

- 先做能点开看到的最小版本，再扩展。
- 小步可验证，避免无边界重构导致「越改问题越多」。
- 破坏性操作前用一句话说明影响并等待确认，其余直接执行。
- 每个阶段结束都留 changelog。
