# 协作体验日志模板

> 适用目录：`logs/<platform>/`，例如 `logs/trae-windows/`
> 文件命名：`YYYY-MM-DD-<简短主题>.md`；同一天多篇时追加 `-02`、`-03`
> 内容语言：中文；命令、路径、代码保留原文

## 一、Front Matter 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `date` | 是 | 记录日期，格式 `YYYY-MM-DD` |
| `timezone` | 是 | 时区，例如 `Asia/Singapore` |
| `platform` | 是 | 运行平台，例如 `trae-windows` |
| `agent` | 是 | 模型或会话标识 |
| `repo` | 是 | 仓库，格式 `owner/repo` |
| `task_type` | 是 | `研究` / `开发` / `文档` / `运维` / `其他` |
| `outcome` | 是 | `成功` / `部分成功` / `失败` |
| `tags` | 否 | 关键词数组 |

## 二、正文结构（按顺序）

1. **会话概览**：目标、结果、涉及文件。
2. **任务与约束**：需求边界、环境限制、不可违反的规则。
3. **执行过程**：用表格记录“动作 → 结果”，只写关键步骤。
4. **体验观察**：
   - 4.1 有效做法：可复用的正向经验。
   - 4.2 卡点与问题：每条按“现象 / 根因 / 处理”展开。
5. **改进建议**：分别面向 Agent、仓库、用户。
6. **可复用结论**：下次可直接照做的短句清单。
7. **元数据**：对话轮次、工具调用次数、产出提交。

## 四、写作要求

1. 只写事实，避免空泛评价；问题尽量给出可验证的根因。
2. 建议必须可执行，避免“加强”“优化”这类无动作描述。
3. 不记录密钥、令牌、密码、PII 或内网地址。
4. 一次会话一篇日志，跨任务时拆分为多篇。
5. 若模板字段不足以表达，可在正文追加章节，不要删减必填项。
